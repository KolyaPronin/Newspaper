# **Newspaper**

Пример проекта «Система совместной работы редакции», который включает в себя:
* **newspaper/**: Фронтенд (React + TypeScript, Create React App)
* **newspaper_backend/**: Бэкенд (Node.js + Express + Mongoose + JWT)

На данный момент реализован следующий функционал: авторизация и роли, рабочий процесс со статьями, управление иллюстрациями, верстка страниц, а также (новое) **панель задач (Task Board) для верстальщика**.

## **Структура каталогов**
* **newspaper/**: Фронтенд-приложение (по умолчанию `http://localhost:3000`)
* **newspaper_backend/**: Бэкенд API (по умолчанию `http://localhost:3001`, префикс API `/api`)

## **Требования к среде**
* **Node.js** (рекомендуется 18+; проект также работает на более новых версиях)
* **npm**
* **MongoDB** (локальная или удаленная БД)

---

## **Запуск бэкенда (API)**
Перейдите в директорию `newspaper_backend/`:

1.  **Установка зависимостей:**
    `npm install`
2.  **Настройка переменных окружения:**
    Скопируйте и измените `.env` (см. `.env.example`):
    * `MONGODB_URI`: Строка подключения к MongoDB (по умолчанию `mongodb://localhost:27017/newspaper_db`)
    * `JWT_SECRET`: Секретный ключ JWT
    * `CORS_ORIGIN`: Разрешенный домен фронтенда (по умолчанию `http://localhost:3000`)
3.  **Запуск:**
    `npm run dev`
    *Проверка состояния (Health check):* `GET /api/health`

---

## **Запуск фронтенда (Web)**
Перейдите в директорию `newspaper/`:

1.  **Установка зависимостей:**
    `npm install --legacy-peer-deps`
    *Примечание: Из-за конфликтов в дереве зависимостей (например, между React 19 и ограничениями некоторых пакетов) используйте флаг `--legacy-peer-deps`.*
2.  **Запуск:**
    `npm start`
    *Для указания адреса бэкенда можно использовать переменную окружения:*
    `REACT_APP_API_URL`: например, `http://localhost:3001` (префикс `/api` добавится автоматически).

---

## **Роли и доступ**
После входа в систему фронтенд перенаправляет пользователя в соответствующую рабочую область в зависимости от роли (см. `newspaper/src/pages/Dashboard/Dashboard.tsx`).

* **layout_designer (Верстальщик)**: Включает рабочую область верстки и переключатель на **«Панель задач» (Tasks)**.

---

## **API задач (Tasks)**
Бэкенд предоставляет интерфейсы для управления задачами (требуется авторизация с заголовком `Authorization: Bearer <token>`):

* **GET /api/tasks**: Получение списка задач (поддерживается фильтрация через query).
* **POST /api/tasks**: Создание задачи (только для `layout_designer` / `chief_editor`).
* **GET /api/tasks/:id**: Получение задачи по ID.
* **PUT /api/tasks/:id**: Обновление задачи (пользователи без привилегий могут менять только `status`).
* **DELETE /api/tasks/:id**: Удаление задачи (только для `layout_designer` / `chief_editor`).

**Сущность задачи включает:** заголовок, описание, дедлайн (deadline), ID выпуска (issueId), назначение конкретному пользователю или роли.
